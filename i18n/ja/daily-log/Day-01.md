## なぜ IDC なのか

## 企画書

### 状況

(株)チョンマーケットは社員20名規模のオンラインショップだ。クラウド費用が増え続けたため、IDC のラックを1つ借りてサーバーを自社運用することにした。私はインフラ担当者だ。

### 要件

| ID | 要件 | どうやって |
| --- | --- | --- |
| R1 | インターネットから `https://www.jjongmarket.kr` でショップにアクセス | FW DNAT → Web VIP → Apache |
| R2 | Web サーバーが1台落ちてもショップを維持 | keepalived VRRP |
| R3 | 必要なポートだけを開く | nftables デフォルト拒否 |
| R4 | サーバー管理は管理網からのみ、在宅は VPN | VPN → MGMT のみ許可 |
| R5 | 内部と外部で異なる DNS 応答 | BIND9 view |
| R6 | 商品データの保管とバックアップ | MariaDB + 毎日ダンプ + 別サーバーに保管 |
| R7 | 状態を一画面で | Prometheus + Grafana |
| R8 | 次の担当者が再構築できるように | ドキュメント + Ansible |
| R9 | HTTPS 警告なし | プライベート Root CA |
| R10 | 全サーバーの時刻を一致 | chrony |

### 制約

- VMware Workstation、Debian 13.2、VM 8台 (サーバー6台 CLI、クライアント2台 GUI)
- Host-only ネットワークのみ使用。インターネットはない想定で、パッケージをインストールするときだけ NAT アダプターを一時的に付ける
- 大会の練習のように「動けば」終わりではなく、なぜそうしたのかを説明できなければならない
